# Rhythm Analyzer -- Architecture

Version 0.1.9 | Python 3.13+ | Plotly/Dash + Web Audio API

---

## Overview

The app records microphone audio while a metronome plays, detects percussion
onsets in the recording, and displays timing deviation statistics relative to the
metronome beat grid. It runs as a single-page Plotly/Dash web app, deployed to
Plotly Cloud.

**Source files (non-trivial):**

| File | Lines | Role |
|---|---|---|
| `app/main.py` | 2641 | Dash layout, Python callbacks, app wiring |
| `app/recorder.js` | 1475 | All in-browser audio I/O and state machine |
| `app/audio_utils.py` | 674 | Pure audio processing, figure builders, metronome track generation |
| `app/exercises.py` | 290 | Exercise text format, parser, and built-in exercise data |
| `app/data_samples.py` | generated | Base64-embedded WAV samples (generated by `dev/embed_samples.py`) |

## Two-Layer Architecture

```
  BROWSER (recorder.js)                     SERVER (main.py + audio_utils.py)
  ========================================  =========================================
  Web Audio API playback (metronome)        librosa onset detection
  MediaRecorder capture (microphone)        soundfile I/O
  OfflineAudioContext downsample to 4 kHz   Plotly figure generation
  WAV encode (encodeWAV)                    YAML settings I/O
  Dash hidden-component message bus <-----> Dash hidden-component message bus
```

**Key constraint:** Dash server callbacks are Python functions fired by Dash's
WebSocket-over-HTTP protocol.  The browser and server cannot call each other
directly.  All coordination passes through hidden Dash components
(`dcc.Store`, hidden `dcc.Input`, hidden `dbc.Button`) acting as a
one-way message bus.

See [callbacks.md](callbacks.md) for the complete callback reference.
See [timing.md](timing.md) for the calibration model and known timing quirks.

## Startup Sequence

```
1. Page loads
   main.py inlines recorder.js into <head> at import time (RECORDER_INLINE_SCRIPT).
   Dash assets_ignore suppresses the file from normal asset serving.

2. recorder.js: window.addEventListener('load', ...)
   After 1 s delay: triggerPermissionDialog() requests microphone permission.
   Opens AudioContext. Routes mic through a muted gain node for INITIAL_WARMUP_SECONDS (8 s).
   Simultaneously plays a silent buffer to prime the output pipeline.
   On completion: writes JSON platform info to #warmup-info-store (hidden input).

3. Dash: warmup-info-store clientside callback fires
   Checks user-context (localStorage) for a saved calibration for this platform_key.
   If found: restores calibration-offset-store + calibration-value silently.
   If not found: calls recorderControls.startCalibration() -- auto-calibration runs.

4. Dash: calibration-track-store clientside callback fires at startup
   Passes precomputed calibration WAV ({data_url, first_beat_ms}) to
   recorderControls.loadCalibrationTrack(), which decodes it into calibrationTrackBuffer.

5. Dash: update_metronome_track fires (prevent_initial_call="initial_duplicate")
   Builds the metronome loop WAV from default settings, stores data URL in
   metronome-track-store.
   Clientside callback passes it to recorderControls.loadMetronomeTrack() for eager decode.

6. Dash: warmup-info-store clientside callback enables Record and Calibrate buttons.
```

## Recording Flow

```
User click: record-btn
  |
  v
clientside_callback -> recorderControls.toggleRecording(n_clicks, phase, ...)
  |
  +-- phase == 'idle':  startRecordingWithCountIn()
  |     getUserMedia() -- request mic
  |     configureMediaRecorder(stream)
  |     stopMetronomePlayback()
  |     startMetronomePlayback({bufferOffsetOverride}) -- count-in measure(s)
  |     recordingDelayTimeout -> beginActiveRecording()
  |       mediaRecorder.start(100ms timeslice)
  |       setRecordingPhase('recording')
  |
  +-- phase == 'delay': cancelPendingRecording()
  |
  +-- phase == 'recording': stopActiveRecording()
        mediaRecorder.stop()
        [triggers mediaRecorder 'stop' event]

mediaRecorder 'stop' event:
  Blob(audioChunks) -> FileReader -> ArrayBuffer
  decodeAudioData (native browser sample rate)
  OfflineAudioContext: resample to 4000 Hz + low-pass at 1800 Hz
  Trim RECORDING_PRE_ROLL_MS (200 ms) from front
  encodeWAV -> DataURL
  window.recordedAudioData = dataUrl
  clickHiddenButton('audio-process-btn')

Dash: audio-process-btn clientside callback
  Reads window.recordedAudioData -> audio-data-store

Dash: show_analyzing_message
  Input: audio-data-store -> status-msg = "Analyzing..."

Dash: process_audio (Python)
  Input: audio-data-store
  State: tempo, beats_per_measure, measures_per_pattern, subdivisions_per_beat,
         calibration_offset_ms, exercise_name
  - Decode base64 WAV with soundfile; fall back to librosa via temp file
  - trim_audio_tail (remove 0.25 s stop-click)
  - compute_spectrum
  - normalize_waveform_for_display
  - detect_onsets_rms -> beat_times, onset_env_norm, hop_length
  - build_waveform_figure
  Output: audio-store (JSON blob), waveform-visible-store=True, waveform-graph figure,
          status-msg=""

Downstream cascade (all triggered by audio-store):
  update_analysis      -> analysis-data-block
  update_subdivision_table -> subdivision-table-container
  update_interval_histogram -> interval-histogram figure
  update_deviation_graph -> deviation-graph figure
  update_spectrum      -> spectrum-graph figure
  (clientside) audio-store -> window.lastRecordedAudio (playback sync)
```

## Calibration Flow

```
Auto-trigger (startup): warmup-info-store callback -> startCalibration()
Manual trigger: calibrate-btn click -> clientside callback -> startCalibration()

startCalibration() (recorder.js):
  Cancel any stale safety-net timer.
  Flip calibrationMode = true, calibrationRecordingEnded = false.
  getUserMedia()
  configureMediaRecorder(stream)
  ctx.resume()
  Play calibrationTrackBuffer (one-shot, no loop) at ctx.currentTime + FIRST_TONE_DELAY_SECONDS
  recordingDelayTimeout at (FIRST_TONE_DELAY_SECONDS * 1000 + calibrationFirstBeatMs - 200 ms)
    -> mediaRecorder.start(100ms)
  recordingTimeout at (track.duration * 1000 + 500 ms)
    -> calibrationRecordingEnded = true
    -> mediaRecorder.stop()
  calibrationSafetyNetTimeout at 20 s
    -> cancels hanging calibration if stop never fires

mediaRecorder 'stop' event (calibration branch):
  [Same WAV encode chain as recording]
  window.calibrationRecordedAudio = dataUrl
  clickHiddenButton('calibration-process-btn')

Dash: calibration-process-btn clientside callback
  -> calibration-audio-data-store

Dash: process_calibration (Python)
  Input: calibration-audio-data-store
  State: debug-mode-store, warmup-info-store
  - Decode audio
  - trim_audio_tail, normalize_waveform_for_display
  - detect_onsets_rms -> beat_times
  - beat_times % seconds_per_beat -> residuals, wrap to (-spb/2, spb/2]
  - median(residuals) -> phase_offset_s -> offset_ms
  - If std >= CALIBRATION_FAIL_STD (1.5 ms): failure path
  - Else: write offset_ms to calibration-offset-store, calibration-value
  - Build new_context {platform_key, calibration_offset_ms, timestamp}
    -> user-context (localStorage)

Calibration value persists across page loads via user-context localStorage store.
Auto-calibration is skipped on reload if platform_key matches.
```

## Metronome Playback Flow

```
Parameter changes (tempo, beats, measures, play-hi, play-only-low, exercise, voicing):
  Python: update_metronome_track
    compute_metronome_track() in audio_utils.py
    Returns base64 WAV data URL -> metronome-track-store

  Clientside: metronome-track-store -> recorderControls.loadMetronomeTrack(dataUrl)
    Sets pendingMetronomeTrackUrl, clears metronomeTrackBuffer.
    Calls _decodeMetronomeTrack -> decodes into metronomeTrackBuffer.
    If metronome was playing (standaloneIsPlaying), restarts playback with new buffer.

User click: metronome-btn
  Clientside -> recorderControls.toggleMetronome()
    if not is_playing: startMetronomePlayback({preserveOffset: false})
      ctx.createBufferSource() with metronomeTrackBuffer, loop=true
      gainNode at metronomeState.volume
      source.start(startTime, bufferOffset)
      setInterval(10ms) -> visual beat indicator updates (highlightBeatIndicator
                           or highlightExercisePosition)
    if is_playing: stopMetronomePlayback()

Debounce: Dash double-fire suppression
  toggleMetronome checks if a "Stop" arrives within 2 s of the last "Start".
  If so, suppresses the Stop (it is a Dash callback chain echo, not a user action).
```

## Exercise System

### Data Model

```
exercises_text (exercises.py) -> make_exercises() -> exercise_dict

exercise_dict: {name -> exercise}
exercise:      {total_beats: int, patterns: list[pattern]}
pattern:       {beats_per_measure, subdivisions_per_beat,
                subdivision_line: str, measures: list[str]}
measure:       string of voicing characters, length = beats_per_measure * subdivisions_per_beat
```

Voicing characters (`voicing_code`):
`x` any, `B` base, `l` low, `h` high, `s` slap, `t` tone, `F` flam,
`m` mute, `q` quiet, `.` ghost note (rest position).

### Exercise in the UI

When an exercise is selected:
1. `update_exercise_ui` shows exercise-specific controls (play-tones, exercise-voicing).
   Sets beats_per_measure, measures_per_pattern, subdivisions_per_beat from the exercise.
2. `update_beat_indicator_boxes` replaces the simple beat boxes with the full exercise table.
3. `update_exercise_schedule` computes `{schedule, duration, spb}` -> exercise-schedule-store.
   Each schedule entry: `{time, patternIdx, measureIdx, subIdx, isBeat}`.
4. Clientside: exercise-schedule-store -> recorderControls.setExerciseSchedule().
   The 10 ms metronome scheduler loop uses binary search on the schedule to call
   `highlightExercisePosition(patternIdx, measureIdx, subIdx)`.
5. `update_metronome_track` generates a WAV track with exercise voicings mixed in.

Custom exercises are defined in the settings YAML under `custom-exercises:` as a
multi-line string using the same text format. They are parsed by `make_exercises()`
inside `load_settings` and merged with built-in exercises via `get_all_exercises()`.

## Audio Processing Pipeline (Python)

```
Raw WAV bytes (base64, 4 kHz, mono, 16-bit PCM)
  |
  v
soundfile.read()  (or librosa via temp file on failure)
  |
  v
trim_audio_tail()
  Remove last AUDIO_STOP_CLICK_TRIM_SECONDS (0.25 s) to eliminate stop-click artifact.
  |
  v
compute_spectrum()  [runs on pre-normalization signal]
  Resample to 4000 Hz, Welch PSD, log-spaced output at FFT_DISPLAY_POINTS (500) points.
  |
  v
normalize_waveform_for_display()
  Clip at 98th percentile of |y|, then normalize to [-1, 1].
  |
  v
detect_onsets_rms(y, sr, hop_ms=1.0, smooth_ms=5.0)
  hop = max(1, sr * hop_ms / 1000)           -- ~1 sample at 4 kHz
  Compute per-hop RMS energy (reshape + sqrt of mean squares).
  Smooth RMS with 5-frame boxcar.
  onset_strength = positive first-difference of smoothed RMS.
  Normalize by Nth largest candidate peak (N=ONSET_ROBUST_PEAK_RANK=3).
  find_peaks with height=BEAT_MIN_AMPLITUDE_FRACTION (0.4),
               distance=BEAT_MIN_SPACING_SECONDS / hop_ms frames (80 ms).
  Returns (onset_times, onset_frames, onset_env_norm, hop).
  |
  v
beat_times -= WAVEFORM_DISPLAY_SHIFT_SECONDS (0.002 s)   [cosmetic x-axis alignment]
  |
  v
Metronome time arrays:
  cal_s = calibration_offset_ms / 1000
  metronome_times = arange(cal_s, duration - 0.1, seconds_per_beat)
  metronome_times_display = arange(cal_s % spb, duration - 0.1, seconds_per_beat)
  |
  v
build_waveform_figure()
  smooth_waveform_for_display (9-frame boxcar)
  downsample_waveform_preserve_peaks (factor 12: keep per-block min and max)
  Pattern/measure/beat markers as diamond scatter (red/orange/royalblue).
  Subdivision tick marks as vertical line markers (black).
  Pulse markers as green circles at y = -1.1.
  Onset envelope overlay as magenta line (optional, SHOW_ONSET_ENVELOPE flag).
```

## Metronome Track Generation (audio_utils.py)

`compute_metronome_track(tempo, beats_per_measure, measures_per_pattern, ...)`

1. Compute `pattern_duration` or `cycle_duration` (exercise mode).
2. Choose `n_patterns` (or `n_cycles`) to reach ~30 s loop, capped at 300 s.
3. For each beat position, call `_get_tick(sr, tone_type, vs, vc_char)`:
   - `synthesized`: `_make_synth_tick` -- sine wave * exponential decay.
   - `djembe` / `darbuka`: `_load_sample` -- reads from `app/assets/{vs}/{name}.wav`
     or `_EMBEDDED_SAMPLES` (data_samples.py), falls back to synthesized.
4. Normalize peak to 0.9, encode as WAV, return as base64 data URL.

`_sample_cache: dict[(vs, name, sr), np.ndarray]` -- module-level LRU-free cache.

`compute_calibration_track()` generates the one-shot calibration WAV at startup:
  `CALIBRATION_WARMUP_MS` (200 ms) silence prefix + `CALIBRATION_BEATS` (10) high tones
  at `CALIBRATION_BPM` (200 BPM). `first_beat_ms` tells JS where beat 1 starts.

## Analysis Outputs

### Subdivision Table (`update_subdivision_table`)

**Free metronome mode:** One table, rows = measures, columns = beats * subdivisions.
Each cell shows `median_ms:count` and is color-coded:
- Green: |median| < warn_ms
- Orange: |median| < alert_ms
- Red: |median| >= alert_ms
- Gray empty: no pulses

**Exercise mode:** One table per pattern, plus a label column (M1, M2, ...).
Header row = subdivision_line characters. Ghost note cells (`.` voicing) use
black background when pulses are detected there.

Thresholds from `TRAINING_LEVEL`:
- Advanced: green < 7.5 ms, orange < 15 ms
- Intermediate: green < 10 ms, orange < 15 ms
- Novice: green < 15 ms, orange < 30 ms

### Deviation Graph (`update_deviation_graph`)

Two overlaid series:
1. **Relative to metronome** -- vertical lines from y=0 to deviation_ms for each
   pulse. Color = green/orange/red by absolute deviation vs training level thresholds.
2. **Relative to previous pulse (IPI)** -- larger royalblue dots at ipi_dev_ms for each
   pulse (except the first). IPI deviations are immune to calibration errors.

X-axis is synchronized with waveform zoom via `relayoutData`.

### Analysis Text Block (`update_analysis`)

Markdown showing: pulse count, beat count, pulses/beat, mean, median, std, min, max
of deviations from the nearest subdivision boundary. Respects waveform zoom window.

### Interval Histogram (`update_interval_histogram`)

Bar chart of inter-pulse intervals in ms. Useful for identifying metrical groupings.

## Settings System

**Session flow:**

```
Page load:
  startup-applied-store = False
  local-settings-store (localStorage) -> settings-raw-store {content, ts}
  -> load_settings() Python callback -> updates all 18 setting components
  -> auto-save clientside callback -> local-settings-store (triggers again)
  startup-applied-store = True -> subsequent triggers are no-ops

Load from file (Settings -> Load Settings):
  Clientside: open file picker, read YAML text
  window.dash_clientside.set_props('settings-raw-store', {data: {content, ts}})
  -> load_settings() Python callback

Save (Settings -> Save Settings):
  save_settings() Python callback -> dcc.Download YAML file

Default (Settings -> Default Settings):
  default_settings() -> settings-raw-store = {content: DEFAULT_SETTINGS_YAML}
  -> load_settings() fires
```

Custom exercises are in the `custom-exercises:` YAML key as a block scalar.
They are parsed inside `load_settings` and stored in module-level `_custom_exercises`.
The settings YAML is always saved without the debug-mode flag set.

## Error Routing

| Error path | Mechanism |
|---|---|
| JS runtime error (unhandled rejection) | `reportJsError()` -> `set_props('error-store', ...)` |
| Python callback exception | `return ... f"Error: {e}"` or `raise PreventUpdate` |
| Calibration failure (high std) | `process_calibration` writes red span to `calibration-confidence` |
| YAML parse error in settings | `load_settings` writes error text to `error-store` |
| Metronome track too long | `update_metronome_track` -> `status-msg` |
| Audio load failure | `process_audio` / `load_recording` -> `error-store` |
| Microphone denied | `reportJsError('Microphone access denied: ...')` |
| Metronome decode error | `reportJsError('Metronome track decode error: ...')` |
| Calibration track decode error | `reportJsError('Calibration track decode error: ...')` |
| Chunk load (Brave restore) | Auto-reload IIFE polls `/_dash-dependencies` |

`error-store` (dcc.Store) is the canonical error bus:
- Clientside callback shows `error-msg-row` with Clear button.
- Separate clientside callback plays a 220 Hz sine beep.

`status-msg` (html.Div, class fw-bold) carries transient status messages.
A clientside callback plays a 220 Hz beep if the message contains
`error`, `invalid`, `failed`, or `syntax`.

## Data Stored in audio-store JSON

```json
{
  "audio":                "data:audio/wav;base64,...",
  "tempo":                120,
  "beats_per_measure":    4,
  "measures_per_pattern": 1,
  "calibration_offset_ms": -164,
  "metronome_times":      [0.082, 0.582, ...],
  "beat_times":           [0.081, 0.493, ...],
  "spectrum_freqs":       [...],
  "spectrum_psd":         [...],
  "duration":             8.32,
  "exercise_name":        null
}
```

`metronome_times` are cal_s-shifted absolute times (used for analysis).
`metronome_times_display` is computed on the fly from cal_s % spb (never stored).
`beat_times` already have `WAVEFORM_DISPLAY_SHIFT_SECONDS` subtracted.
The JSON is saved as-is to disk (`Save as JSON`) and round-trips cleanly through
`load_recording`.

## Refactoring Suggestions

### 1. Split main.py (most valuable)

At 2641 lines, `main.py` is hard to navigate. The natural splits are:

```
app/layout.py           -- Dash layout tree (app.layout = ..., app.index_string = ...)
app/callbacks_audio.py  -- process_audio, load_recording, save_recording, export_wav
app/callbacks_analysis.py -- update_analysis, update_subdivision_table,
                              update_deviation_graph, update_interval_histogram,
                              update_spectrum
app/callbacks_calibration.py -- process_calibration, calibration_value_edited,
                                 and all calibration clientside callbacks
app/callbacks_metronome.py   -- update_metronome_track, update_beat_indicator_boxes,
                                 update_exercise_ui, update_exercise_schedule,
                                 enforce_tone_toggle_exclusion, and metronome clientsides
app/callbacks_settings.py    -- save_settings, load_settings, default_settings,
                                 and the localStorage auto-save clientsides
app/callbacks_ui.py          -- button label updates, error routing, visibility clientsides
```

Dash requires all callbacks to be registered before `app.run()`. Each module just
needs to import `app` from a shared `app_instance.py` (or `__init__.py`) and define
its callbacks at module scope. `main.py` becomes the entry point that imports them all.

### 2. Dead stores

`metronome-points-store` and `pulse-points-store` are declared in the layout but no
callback reads or writes to them. They can be removed without side effects.

### 3. Dead function: filter_beat_times

`audio_utils.filter_beat_times()` (line 278) is defined but never called. Its
amplitude and spacing filtering is already handled inside `detect_onsets_rms`.
Delete or document as internal.

### 4. Duplicate audio-loading pattern

The soundfile-then-librosa fallback appears three times:
`process_audio` (main.py:2124), `load_recording` (main.py:2298),
`process_calibration` (main.py:713). Extract to a helper:

```python
def load_audio_bytes_robust(audio_bytes: bytes) -> tuple[np.ndarray, int] | None:
    try:
        with io.BytesIO(audio_bytes) as f:
            y, sr = sf.read(f)
        return y, sr
    except Exception:
        return load_audio_from_bytes(audio_bytes)
```

### 5. is_debug_mode couples audio_utils to the Dash app

`is_debug_mode()` in `main.py` reads `app.server.debug`. If `audio_utils.py` ever
needs debug mode passed in, pass it explicitly rather than importing the Dash app.
Currently this is fine since `is_debug_mode` is only in `main.py`.

### 6. Magic constant for RECORDING_PRE_ROLL_MS

`RECORDING_PRE_ROLL_MS = 200` in `recorder.js` and related math in
`startRecordingWithCountIn` / `startCalibration` are sprinkled in several places.
Document the invariant: the pre-roll ensures that `beat 1 of the recording aligns
with t=0 after the pre-roll is trimmed`. Consider adding an assertion or comment
tying the JS constant to the Python `WAVEFORM_DISPLAY_SHIFT_SECONDS`.

### 7. Eager AudioContext creation on page load

`loadMetronomeTrack` and `loadCalibrationTrack` create an `AudioContext` eagerly
(before user gesture) so the track can be decoded in the background. Browsers may
suspend this context. The suspension is handled (context is resumed inside user
gesture handlers), but a stale suspended context at calibration time was a prior
bug source. Consider a single `ensureAudioContext()` call at warmup rather than
multiple creation sites.

### 8. Cross-platform operability

**Safari:** The CLAUDE.md notes an HTMLAudio fallback for Safari, but the current
`recorder.js` uses Web Audio exclusively for metronome playback. Verify whether
Safari correctly handles `AudioContext` looping of a decoded `AudioBuffer`. The
`webkitAudioContext` prefix is guarded (`window.AudioContext || window['webkitAudioContext']`).
Safari also restricts `getUserMedia` in some contexts; test on Safari iOS.

**Firefox:** `MediaRecorder` on Firefox may prefer `audio/ogg;codecs=opus` over
`audio/webm`. The `buildRecorderOptions()` MIME type priority list handles this,
but the fallback path through `load_audio_from_bytes` requires ffmpeg to decode
OGG on the server. Verify ffmpeg is available on Plotly Cloud.

**Plotly Cloud workers:** The Cloud deployment uses Gunicorn workers; each worker
process has its own `_sample_cache` and `_custom_exercises`. Settings loaded in
one worker are not visible in another. Custom exercises from uploaded YAML are
session-scoped (per-worker), which is acceptable for single-user use but would
be a problem for shared deployments.

### 9. Calibration robustness improvements

See [timing.md](timing.md) for detailed calibration analysis. Key open issues:

- `CALIBRATION_FAIL_STD = 1.5 ms` rejects calibrations that succeed acoustically
  but have one outlier beat. Raising to 3-5 ms with outlier trimming (median + IQR)
  would be more robust.
- Auto-calibration at startup runs `calibrationWarmupMeasures = 3` (warm path) or
  `1` (cold path); the distinction is not currently implemented. Both use 3.
- The safety-net timeout is 20 s. If the OS takes longer to open the mic on first
  launch, the safety net fires before the recording completes. Making the safety net
  responsive to the actual track duration would be safer.
- Calibration currently assumes uniform metronome tempo. Any tempo drift or
  AudioContext jitter contributes to cal_s error. Adding a check that the IPI
  of detected beats matches CALIBRATION_BPM would catch decoding/playback drift.

### 10. Waveform display and analysis decoupling

All analysis callbacks (`update_analysis`, `update_subdivision_table`,
`update_deviation_graph`, `update_interval_histogram`) re-parse the audio-store
JSON independently. A single shared function that extracts the common fields
(beat_times, metronome_times, tempo, cal_s, zoom window) would reduce redundancy.
